Shape 账本：先把这些看顺

矩阵乘法只先记一条：[..., A, B] @ [..., B, C] = [..., A, C]。中间维度对上，结果留下两边。

GPT 里最常见的形状

对象常见 shape意思
token ids[B, T]B 个样本，每个样本 T 个 token。
embedding[B, T, d]每个 token 变成 d 维向量。
Q / K / V[B, h, T, d_head]多头注意力里的查询、键、值。
attention scores[B, h, T, T]每个 token 对每个 token 的注意力分数。
logits[B, T, vocab]每个位置对整个词表打分。

Attention 的最小推导

Q: [B, T, d_head]
K: [B, T, d_head]
Kᵀ: [B, d_head, T]

Q @ Kᵀ
= [B, T, d_head] @ [B, d_head, T]
= [B, T, T]

softmax(scores) @ V
= [B, T, T] @ [B, T, d_head]
= [B, T, d_head]

直觉：每个 token 先给前文 token 打分，再按权重把它们的 value 混合成自己的新表示。

后面再补，不要一开始就补

这些都重要，但顺序要放后面。先把 tiny GPT 的计算链路打通，再补现代 LLM 组件。

RoPE：模型怎么知道位置先要直觉，公式后置
先理解 positional embedding 解决“顺序”问题。RoPE 用旋转方式把相对位置信息注入 Q/K。起步阶段不需要硬推复数旋转公式。
KV cache：为什么生成可以缓存理解推理成本
生成第 n 个 token 时，前面 token 的 K/V 可以复用；只需要算新 token 的 Q，再和缓存 K/V 做 attention。这解释了长上下文为什么贵。
LoRA：为什么微调可以只改少量参数低秩更新
不用直接改完整大矩阵 W，而是在旁边加一个低秩更新 ΔW≈AB。直觉上是用小参数量表达常见的微调方向。
RLHF / DPO：base model 怎么变成 chat model偏好优化
先记顺序：pretraining 学续写，SFT 学按指令回答，preference optimization 学人类偏好。PPO 细节可以很晚再看。
解释性：logit lens、SAE、Jacobian lens等 GPT 看完再回头
先有 residual stream、logits、attention、MLP 的计算图直觉，再看解释性会清楚很多。否则 J-space、SAE feature、activation patching 容易变成玄学词。
